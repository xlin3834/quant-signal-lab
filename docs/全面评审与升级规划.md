# Quant Signal Lab 全面评审与升级规划

评审日期：2026-11-25。代码基线是 `main` 的 `b0d6972`（P1 Bitget USDT 永续目录）。开放中的 [PR #1](https://github.com/xlin3834/quant-signal-lab/pull/1) 只处理研究图表和未收盘 K 线，不是这次要搭的平台，本文不把它算进已交付功能。

这次交付分两部分：下面的现状、边界和设计；以及研究平台的第一版可运行切片。第一版接上了当前环境能够访问的官方公开接口，并把需要密钥、区域不可用或文档未能核对的来源明确标成阻塞。没有示例交易员，也没有示例盈亏。

## 1. 仓库里实际有什么

仓库是一个 Streamlit 应用，入口 `quant_signal_lab_online/app.py`。没有独立前端，没有 FastAPI，也没有用户账号。依赖只有 Streamlit、pandas、NumPy、requests、Plotly、websocket-client。

| 模块 | 文件 | 现状 |
| --- | --- | --- |
| Bitget 现货行情 | `market_data.py` | 只拉 BTCUSDT、ETHUSDT、SOLUSDT。周期 5m、15m、1H、4H、1D。只把已收盘 K 线交给指标。请求间隔 0.15 秒，失败重试 |
| 现货报价诊断 | `live_market.py`、`quote_ui.py` | 可选网关只推三个现货 ticker。页面能区分 WebSocket 和 REST，并拒绝过期报价 |
| 指标 | `indicators.py` | EMA、布林、RSI、MACD、ATR、均量、前移后的支撑压力。固定窗口，避免换下载长度就改已算完的值 |
| 信号 | `signals.py` | 15 分钟收盘触发。4 小时和 1 小时同向 30 分，动量 20，成交量 20，形态 15，ATR 占比 15。阈值默认 65/80，盈亏比默认 1.5 |
| 回测 | `backtest.py` | 下一根开盘成交，手续费和滑点，同根先止损，跳空按更差的开盘价。70/30 时间切分，阈值只在样本内选择 |
| 旧 EMA 策略 | `legacy.py` | 保留作对照，只做多 |
| 模拟账户 | `paper.py` | 单独进程和单独 SQLite。一个库一个现货、一笔 1 倍仓。没有交易所下单 |
| USDT 永续目录 | `perpetual_market.py`、`perpetual_ui.py` | 官方合约列表和 ticker。搜索、排序、成交额和价差过滤、URL 自选。只读，没有永续 K 线、评分或模拟成交 |
| 图表 | `charts.py` | Plotly K 线。没有 Hyperliquid，没有交易员监控 |

模拟库只有三张表：`account` 的整段 JSON、`trades`、`equity`。没有来源、接收时间、延迟、证据等级或自选交易员。

测试在本次改动前为 28 项，覆盖新鲜度、高周期不看未来、样本外不能反过来选阈值、止损优先和模拟熔断。

## 3. 现有实现的瓶颈和正确性边界

回测要拉 3000 到 5000 根 15 分钟 K 线，再按比例拉 5 分钟、1 小时和 4 小时。历史接口每页 200 根，而且全进程共用 0.15 秒的锁。一次完整回测是上百次串行 HTTP，页面会停在加载提示上。

模拟进程每 30 秒重新拉四个周期。现货工作台约 45 秒刷新，永续约 30 秒，K 线缓存 40 秒。这些缓存不是数据库，进程一停就没了。Streamlit Community Cloud 也没有给模拟进程准备持久磁盘，这一点原来的 README 已经写明。

回测没有使用未来收盘价来决定当时的信号，样本外测试锁住了阈值。仍有这些界限：

- 只优化一个阈值，优化目标是样本内扣成本后的期末盈亏，文档已写明可能过拟合
- 训练和样本外直接相接，没有隔离带
- 做空是研究用的 1 倍对称成交，没有借币，也没有资金费
- 资金费、合约面值和最小名义额还没进成交模型，所以永续回测不能开始
- 现货标的写死三个，不代表整个市场
- `paper.py` 遇到异常时会清掉尚未执行的开仓计划。缺历史或停机超过 5000 根时会保留状态。这次没有改这条路径

布林带用的是 pandas 默认标准差，和 TA-Lib 的总体标准差不一定相同。新指标的 EMA 是截断窗口，`legacy.py` 仍用 `ewm`。两套数字本来就不该混着比较。

## 5. 证据等级

- A：账户主人自己的官方只读接口。本版本不保存密钥，所以不会产生 A 类记录。
- B：交易所公开接口，或公开地址上的官方账户状态。Hyperliquid 地址和 OKX 公开带单都是 B。
- C：社交平台上的公开说法。说法不是持仓。
- D：截图或 OCR。不能当成已验证持仓或收益。

Bitget 最新价对照只计算价差。价差不会改变等级，也不会证明仓位属于某人。页面文案固定为：只对照 Bitget 公开最新价，不能证明该持仓属于该交易员，也不能证明收益。

新鲜度在读取时计算，不把库里的旧状态永久当成有效。`正常` 只表示官方快照还在有效期内，文案同时说明这是轮询而不是逐笔推送。过期、缺少行情时间或时钟倒退都不能称为实时。资金费历史固定标成历史记录。

## 7. 数据模型

新快照不和 `paper.sqlite3` 混用。每条快照至少有：

- `venue`、`entity_key`、`grade`
- `exchange_time_ms`、`received_time_ms`
- `connection_status`：正常、过期、无行情时间、时钟异常、缺失，或探测用的“区域不可用”
- `payload`：接口原样转换后的 JSON
- 读取时再用 TTL 重新计算状态。OKX 榜单用 `dataVer` 作交易所时间，TTL 15 分钟。Hyperliquid 账户 `time` 的 TTL 是 60 秒。Bitget ticker 的 TTL 是 90 秒，和原来的永续报价一致

自选主键是分类加实体键，例如 `hyperliquid:` 加地址、`okx:` 加 uniqueCode、`repo:` 加仓库名。刷新页面后还在。永续页原来的 URL 自选没有改。

文章必须有 `http` 或 `https` 链接。研究者和文章都可以按文字搜索。空库保持空白。

## 8. 不能做，以及为什么

- 不能按 Hyperliquid 昵称搜索。官方 info 只收 42 位地址。
- 不能把未写入官方文档的榜单文件当成稳定接口。
- 不能查询 Binance 上别人的持仓。公开跟单文档没有这个接口，而且当前环境连 ping 都是 451。
- 不能在没有所有者只读密钥时查询 Bitget 跟单。探测已经返回缺少 `ACCESS_KEY`。
- 不能用 Bot API 拉取机器人未加入频道的历史，也不能绕过 Telegram 权限。
- 不能在 X 文档和凭证都没有核对时展示推文。
- 不能把 OCR 或社交帖标成已验证持仓。这两项本版没有接入。
- 不能用价差证明某人赚钱或亏钱。
- 不能把 `userFills` 算出来的胜率写成完整历史胜率。页面写明单次最多 2000 条。
- 不能把 OKX `subPos` 乘价格当成名义额。张数和币数不是一回事，名义额留空。
- 不能为了凑模块去编 meme 币、研究者或文章摘要。
- 不能安装并运行上述第三方交易框架。
- 不能下单，不能自动发布，不能把分支合并进 `main`。这些动作留给仓库所有者。

Hyperliquid 持仓没有开仓时间字段，页面写缺失，不用第一笔成交冒充首次开仓。最大回撤如果来自 `accountValueHistory`，会写明窗口和“不是交易所单独给出的回撤字段”。样本不足时显示缺失，不用 0 代替。

## 9. 验收和后续顺序

本版已经过的验收：

- 原有单元测试仍然通过
- 过期快照不能标成实时
- 截图和社交文案包含“不能当作已验证持仓”
- 价差不升级证据等级
- 均衡预设等于原来的阈值、权重和成本
- 保存一套策略不会改写另一套
- 默认权重下，只有趋势结构成立时仍是 30 分
- 均值回归信号出现在已收盘 K 线，仓位到下一根才出现
- Hyperliquid 解析把空仓丢掉，并把净空标成 short、等级 B
- OKX 榜单解析没有最大回撤
- GPL 仓库不会被标成可并入，安全分保持为空
- Binance HTTP 451 显示为区域不可用
- `QSL_LIVE=1` 时，BTCUSDT 市场结构、Hyperliquid 全 0 地址、OKX 公开榜第一页和 Binance 连通性分类都成功

后续仍按同一条顺序，不跳过人工确认：

1. 把本版的阻塞项收成明确需求：所有者是否提供 Bitget 只读密钥、是否有能访问 Binance 的网络、X 凭证、Telegram 机器人所在的公开频道
2. 复查开源许可，尤其是 Commons Clause、AGPL 和 GPL
3. 设计下一刀只加一个来源，并放在功能分支
4. 用沙箱和录制的公开响应做测试，不把真实盈亏写进仓库
5. 做密钥存储、日志和权限审计。密钥继续只留在环境变量或部署系统
6. 测频率、缓存和页面刷新
