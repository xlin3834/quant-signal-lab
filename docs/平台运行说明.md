# 研究平台运行说明

## 启动

在仓库根目录：

```bash
pip install -r quant_signal_lab_online/requirements.txt
streamlit run quant_signal_lab_online/app.py
```

打开后有三个入口：

- Bitget USDT 永续：原来的只读合约目录
- Bitget 现货：原来的行情、评分、回测和模拟账户。侧栏现在可以选择五套策略
- 研究平台：这次新增的资料和公开监控

研究库默认写到 `quant_signal_lab_online/data/research.sqlite3`。这个目录已忽略，不要提交。换位置时设置 `QSL_RESEARCH_DB`。模拟账户仍用原来的 `QSL_PAPER_DB`，两个库互不覆盖。

## 测试

```bash
cd quant_signal_lab_online
python -m unittest discover -q
QSL_LIVE=1 python -m unittest test_platform_live.py
```

`discover` 会跳过实时测试。`QSL_LIVE=1` 才会请求 Hyperliquid、OKX、Bitget 和 Binance 的公开地址。实时测试只检查字段和状态，不打印昵称、地址或盈亏。

## 可选环境变量

这些变量都不是必须的，也不要写进仓库：

| 变量 | 作用 |
| --- | --- |
| `QSL_RESEARCH_DB` | 研究库路径 |
| `QSL_PAPER_DB` | 原模拟账户路径 |
| `QSL_MARKET_URL` | 原现货 WebSocket 网关 |
| `GITHUB_TOKEN` | 提高 GitHub 公开仓库读取额度。页面不会显示它 |

Bitget 跟单、Binance 私有持仓、Telegram 和 X 即使以后要接，也只从所有者自己的环境读取只读凭证。当前版本没有签名代码，也不会因为机器上存在某个变量就去调用这些私有接口。

## 怎么读页面

交易员页的 Hyperliquid 输入可以是地址，也可以是含有一个 `0x` 地址的链接。多个地址会拒绝。OKX 可以按页读取公开榜，也可以直接输入 `uniqueCode`。搜索只过滤已经下载的那一页。

每一份持仓或行情都会显示状态、行情时间、接收时间和两者的差。过期或没有行情时间时，页面写明不能当作实时。证据等级 B 是公开官方数据，不是账户主人单独授权的只读 Key。

市场结构页的资金费、持仓量和成交来自 Bitget 公开市场，不代表某个交易员。价差列只是和 Bitget 最新价对照。

GitHub 页的安全分固定是“未扫描”。点击刷新才会请求 `api.github.com`。

研究者和文章开始是空的。文章摘要如果存在，来源是手工录入。规则说明页不是对话模型。

任务页能看到 Git 短哈希和模块状态。它不能发布，也不能合并到 `main`。

## 明确不做的事

程序没有下单接口。均值回归只影响现货页的研究和回测，独立模拟进程仍使用原来的趋势评分。不要把截图、社交帖或价差对照说成已验证持仓。
